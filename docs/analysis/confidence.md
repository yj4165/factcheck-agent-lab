# 확신도와 정답 여부

**질문**: 모델이 출력한 확신도(`confidence`, 0–1)는 정답 여부와 관련이 있나? 판정을 채택할지 보류할지 정하는 데 쓸 수 있나?

- 실행: `results/norag_base_n500`, `results/rag_base_k10_n500`, `results/agent_base_k10_n500`, `results/oracle_base_n500`
  (모두 `gpt-5-nano`, AVeriTeC dev 500개)
- 스크립트: [analysis/confidence.py](../../analysis/confidence.py)
- Agent는 출력이 없는 4건을 빼고 496건으로 계산했습니다. 그래서 accuracy가 메인 README(0.532, 500건 기준)와 조금 다릅니다.

## 요약

- **전체로 보면 확신도가 높을수록 정답률이 확실히 높습니다** (AUROC 0.84–0.90). 확신도 0.7 이상만 채택하면
  Agent는 클레임 절반에서 accuracy 0.81, Oracle RAG는 60%에서 0.94입니다.
- **하지만 이 신호의 대부분은 "어떤 라벨을 골랐는가"에서 나옵니다.** Not Enough Evidence 예측은 확신도가 항상 0.7 미만이고
  정답률도 가장 낮습니다(0.09–0.26). 예측 라벨만으로도 정답 여부를 AUROC 0.79–0.85로 맞힐 수 있고, 확신도를 더해도 크게 오르지 않습니다.
- **같은 라벨 안에서는 구분력이 약합니다** (Supported·Refuted에서 AUROC 0.57–0.81). **Conflicting에서는 확신도가 쓸모없습니다** (0.36–0.58).
- **보정은 맞지 않습니다.** 0.5–0.7 구간은 과신하고(확신도 약 0.6, 정답률 0.30–0.52), 0.7 이상 구간은 과소평가합니다(확신도 약 0.77, 정답률 0.81–0.94).

## 결과

### 전체

AUROC는 확신도만 보고 정답과 오답을 구분하는 능력입니다(0.5 무작위, 1 완벽).
ECE는 확신도와 실제 정답률의 평균적인 차이입니다(10구간, 0에 가까울수록 잘 보정됨).

| 방법 | Accuracy | 확신도 평균 | 정답 / 오답 확신도 | AUROC | ECE |
|---|---:|---:|---:|---:|---:|
| No RAG | 0.434 | 0.599 | 0.698 / 0.523 | 0.895 | 0.252 |
| Simple RAG | 0.482 | 0.660 | 0.718 / 0.605 | 0.843 | 0.216 |
| Agent | 0.536 | 0.669 | 0.740 / 0.588 | 0.845 | 0.173 |
| Oracle RAG | 0.766 | 0.710 | 0.738 / 0.618 | 0.864 | 0.147 |

### 확신도 구간별

각 칸은 정답률 (클레임 수)입니다.

| 방법 | 0.5 미만 | 0.5–0.7 | 0.7 이상 |
|---|---:|---:|---:|
| No RAG | 0.06 (125) | 0.38 (239) | 0.88 (136) |
| Simple RAG | 0.00 (16) | 0.30 (300) | 0.82 (184) |
| Agent | 0.02 (47) | 0.31 (197) | 0.81 (252) |
| Oracle RAG | 0.00 (5) | 0.52 (196) | 0.94 (299) |

구간 안에서 Not Enough Evidence 예측이 차지하는 비율은 0.5 미만에서 98–100%, 0.5–0.7에서 40–62%, 0.7 이상에서 0%입니다.

### 임계값 이상만 채택할 때

각 칸은 채택 비율 → 정답률입니다.

| 방법 | conf ≥ 0.7 | conf ≥ 0.75 | conf ≥ 0.8 |
|---|---:|---:|---:|
| No RAG | 27% → 0.875 | 18% → 0.900 | 5% → 0.889 |
| Simple RAG | 37% → 0.821 | 22% → 0.861 | 9% → 0.957 |
| Agent | 51% → 0.813 | 32% → 0.853 | 14% → 0.915 |
| Oracle RAG | 60% → 0.940 | 41% → 0.971 | 15% → 0.987 |

### 예측 라벨 안에서의 구분력

같은 라벨로 예측한 클레임들 안에서, 확신도로 정답과 오답을 가르는 AUROC입니다. 괄호는 그 라벨의 예측 수입니다.

| 예측 라벨 | No RAG | Simple RAG | Agent | Oracle RAG |
|---|---:|---:|---:|---:|
| Supported | 0.81 (47) | 0.64 (89) | 0.59 (92) | 0.77 (91) |
| Refuted | 0.57 (170) | 0.60 (174) | 0.68 (216) | 0.75 (293) |
| Not Enough Evidence | 0.65 (274) | 0.55 (181) | 0.70 (125) | 0.64 (95) |
| Conflicting | 0.58 (9) | **0.36** (56) | **0.47** (63) | **0.48** (21) |

Conflicting 예측은 정답이든 오답이든 확신도가 약 0.62로 같습니다.

정답 여부를 맞히는 로지스틱 회귀를 입력만 바꿔 비교했습니다 (5-fold 교차검증 AUROC).

| 예측 라벨만 | 0.854 | 0.835 | 0.820 | 0.793 |

### 에이전트: 스텝 수와 확신도

스텝 수와 확신도는 반비례합니다 (Spearman ρ = −0.48, p < 1e-28).
스텝 수 구간 안에서도 확신도의 AUROC는 유지되므로, 확신도에는 "얼마나 오래 검색했나" 이상의 정보가 들어 있습니다.

| 스텝 수 | 클레임 수 | Accuracy | 확신도 평균 | AUROC |
|---|---:|---:|---:|---:|
| 2 | 142 | 0.676 | 0.732 | 0.835 |
| 3–9 | 280 | 0.550 | 0.682 | 0.829 |
| 10 | 74 | 0.216 | 0.504 | 0.817 |

(스텝 10은 출력이 없는 4건을 뺀 74건입니다. 스텝 분석 전체는 [agent_steps.md](agent_steps.md) 참고.)

## 해석과 다음 단계

- 확신도는 판정을 채택할지 보류할지 정하는 기준으로 쓸 수 있습니다. 다만 "확신도 0.7 미만은 보류"는
  사실상 "Not Enough Evidence와 애매한 판정은 보류"와 같습니다. Supported·Refuted 중 틀린 답을 골라내는 데는 한계가 있습니다.
- Conflicting 판정을 믿을지 판단하려면 확신도 말고 다른 신호가 필요합니다.
- 확신도 값은 0.58, 0.62, 0.72, 0.78 같은 몇 개 값에 몰려 있습니다 (실행별로 서로 다른 값 36–53개).
  연속적인 확률이라기보다 "낮음 / 중간 / 높음" 정도의 거친 등급으로 보는 것이 맞습니다.
- 확인해 볼 만한 것:
  - 확신도 대신 여러 번 샘플링한 판정의 일치도(self-consistency)가 더 나은 신호인지
  - 확신도 기준을 넣은 하이브리드(예: Agent의 확신도가 낮으면 다른 방법의 판정 사용)
